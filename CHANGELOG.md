# Changelog

## 0.1.0 — unreleased

Standalone Git distribution prepared for `DxTa/pi-sentinel`.

- **Breaking:** config is read only from `~/.pi/agent/sentinel.json` and `<project>/.pi/sentinel.json`. `permissions.json`, the legacy config files, `domain-gate.json`, and the `yoloMode`/`yoloAutoMode` flags are no longer read. Rename `permissions.json` to `sentinel.json`; a warning names the old file when only it exists.
- Renamed the `yolo-auto` mode to `auto`, with no compatibility alias: set `"mode": "auto"`. Environment variables are `PI_SENTINEL_AUTO_MODEL_DIR` and `PI_SENTINEL_AUTO_SOCKET`; the model cache is `runtime/pi-sentinel/auto-mode/models`; calibration logs are `auto-mode-calibration.jsonl`; debug events use the `auto_mode.` prefix.
- `/sentinel` shows each row's effective value and source scope (`manual (project)`, `on (default)`, `off (project, overrides global)`), with a compact one-line mode chain instead of the paged chain.
- Removed the "Mode saves to" row: a mode change saves to the scope that currently sets the mode (session above `PI_SENTINEL_MODE`; global for bundled defaults). Added `/sentinel mode <manual|yolo|auto> [session|project|global]`, with autocomplete for the mode and scope, to store the mode in a specific scope. In the panel, Enter on Mode opens a picker with the current scope plus session and project overrides, limited to scopes where the change takes effect.
- Fixed `/sentinel` writing effective values to the global file: toggling a log setting copied the effective mode and merged `yoloAskBashPatterns` (including project values) into `~/.pi/agent/permissions.json`. Only the changed key is written now.
- Fixed the `/sentinel` sandbox row ignoring a project `sandbox.enabled`, and log toggles applying in-session despite a project override.
- `auto` mode: the worker loads ONNX Runtime before downloading the model, so an unsupported platform or broken install fails immediately instead of after a 130 MB download. Pi warns once when `auto` falls back to prompting, and `/sentinel show` reports `autoModeWorker=stopped` with the log path. A test runs real CPU inference so a broken runtime install fails `npm test`.
- `auto` mode uses the FP16 Lion Warden model by default (~320 MB download, was the ~130 MB int8 build), with JSON tool-call input and per-operation thresholds from `npm run calibrate`. Model settings live in `profiles/models/<id>.json`. MCP tool calls are classified: only calls the model reads as read or list can skip the prompt; destructive-hinted tools and SQL writes always prompt. `rm`, `ssh`, `git push`, package publish and cluster writes now prompt in `auto` even when the model allows. Writes telling an AI agent to drop its rules always prompt. `permission.mcp` patterns apply to `mcp__<server>__<tool>` tools. Writes to agent instruction files (`AGENTS.md`, `CLAUDE.md`, ...) and writes that use secret variables or home credential folders always prompt. `npm run calibrate` sets per-operation thresholds from `scripts/calibration-dataset.json`.
- Install prefetches the `auto` model (~320 MB) best-effort through `postinstall`; a failed or skipped download never fails the install. Skip it with `PI_SENTINEL_SKIP_MODEL_DOWNLOAD=1`, or in CI (`CI` set).
- Fixed `auto` startup stalls: the worker opens its socket first and downloads and loads the model in the background. Until it is ready, classification fails closed (prompt) with `model_loading`, so a slow first download no longer ends as `startup_failed` after 120 s. `pi install` from a git source does not run `postinstall`, so the prefetch above only helps npm installs.
- Reads under `~/.config` are allowed by default; credential files there (gh, gcloud, azure, claude, codex, anthropic, openai, git credentials) stay masked. Reads under the Pi agent directory are allowed in every mode with secret files masked; writes there still prompt.
- `auto` mode: the classifier is the gate for everything not covered by your own `allow` rules. It now judges external writes, edits, Bash and MCP, builtin and bundled `allow` defaults, and forced prompts (`rm`, `ssh`, `git push`, publish, cluster changes). Workspace reads need no model. Sensitive paths (system roots, `~/Library`, credential folders, shell startup files, `.pi/` config writes) and `.env*` grep/find selectors always prompt. Symlink targets are resolved before the sensitive-path check.
- `yolo` mode: workspace calls, pathless tools, and non-sensitive external reads auto-approve; external writes, edits and Bash go to the classifier and prompt when it is unavailable (including Intel Macs). Hard rules still prompt and never reach the model. The classifier worker now starts in `yolo` too. Forwarded subagent requests in `yolo` still auto-approve without the classifier.
- Bash locality for `auto`: system-bin executables and `PATH=` entries, loopback URLs (not `user@host` URLs), and commands that cannot be split (without `cd`) no longer count as external.
- Masked credential files: added GitHub Copilot, acli, Claude Desktop, and `~/.pi/agent` secret files (`mcp-auth.json`, `mcp.json`, `models.json`, `search-config.json`). A symlinked file is masked by its lexical path too. Writes under `~/.config` stay protected.
- Docker and other CLIs: the Docker socket is found again (the native `realpath` fails on sockets on macOS; Rancher Desktop and Colima locations added), and a missing socket no longer blocks the command. All Unix sockets are reachable from every sandboxed command, and sandbox grants no longer refuse socket paths or socket directories. `kubectl`, `helm`, `argo`, `k9s` and `gh` get read-only access to their config (`~/.kube/config`, `gh` `hosts.yml`) without a prompt, like Docker's config; when SRT is unavailable they run on the host instead of being blocked. `/etc/protocols`, `/etc/services`, `/etc/shells` and timezone data are readable in the sandbox. Known gap: `gcloud` still cannot read its masked config directory.
- Rewrote the README around a quick start, mode comparison, and the security-relevant defaults. Detailed reference moved to `docs/reference.md`.
- Linux sandbox no longer needs a system `ripgrep`: the binary ships through `@vscode/ripgrep` (npm platform packages, no install-time download) and is passed to SRT as `ripgrep.command`. `rg` on `PATH` remains the fallback. `/sandbox-status` checks the binary SRT will actually use.
- `/sandbox-status` on Linux runs a short bubblewrap test and prints the fix: the install command for missing packages (apt, dnf, pacman, zypper), or a bwrap-only AppArmor profile when Ubuntu 24.04+'s user-namespace restriction blocks it. Commands blocked for missing dependencies point to `/sandbox-status`.

- Policy denies now prompt instead of blocking: config `deny` rules, yolo forbidden-write paths, `.env*` protection, and push denies show "BLOCKED BY POLICY" and offer allow once or for this session (no workspace/global grant). Yolo and `auto` never auto-approve these prompts; no UI keeps the block. For Bash, a Yes also grants the sandbox one-shot access to ordinary external write targets (no second dialog); system and credential paths keep their separate sandbox prompt. Denied network domains and sandbox auth-exception denies still block.
- Preserved permission, network, sandbox, masked-path, grant, service, and backend behavior.
- Removed content-based credential scanning and approval; configured SRT masks and permission/path rules remain.
- Resolved bundled bubblewrap runner relative to installed package root.
- Removed environment-specific semantic-search trust behavior.
- Excluded private grants, logs, generated state, and parent-repository tests.
- Retained upstream `@gotgenes/pi-permission-system` attribution and MIT license.

Release remains gated on replacing the local sandbox-runtime hardening patch with an equivalent released dependency. SRT 0.0.75 was reviewed: it improves related macOS rule ordering and filtering, but still emits `file-write-create` move blocks for denied roots and ancestors, so it is not treated as equivalent.
